# OVA Review Bot

Discord-бот для канала **«состав»**: по команде читает гугл-документ с анкетой
(«личным делом») и проверяет его на соответствие правилам сервера.

Проверка двухслойная:

1. **Автопроверки** — жёсткие правила из чек-листа: обязательные разделы и поля,
   прочерки вместо текста, минимальный объём, возраст ↔ год рождения, рост/вес,
   запрещённые формулировки. Работают всегда, без ИИ и без ключей.
2. **ИИ-проверка** — смысловой разбор: лор, правдоподобие персонажа, копипаста,
   противоречия между разделами. Включается, если указан ключ модели.

На выходе — вердикт, оценка 0–100, замечания с рекомендациями и подробный
отчёт `.md`-файлом, который можно приложить к ответу автору.

---

## Быстрый старт

Нужен **Node.js 20.6+** (проверено на 24). Дальше:

```bash
cd ova-review-bot
npm install
```

### 1. Создать бота

1. https://discord.com/developers/applications → **New Application**.
2. Вкладка **Bot** → **Reset Token** → скопировать токен.
3. Там же включить **MESSAGE CONTENT INTENT** (нужен, чтобы бот искал ссылку
   в сообщениях топика). Если не включать — бот всё равно запустится, но ссылку
   придётся передавать в команде вручную.
4. Вкладка **OAuth2 → URL Generator**: scope `bot` + `applications.commands`,
   права: *View Channels, Send Messages, Embed Links, Attach Files,
   Read Message History*. Пригласить бота на сервер.

### 2. Настроить `.env`

```bash
copy .env.example .env
```

Заполнить минимум:

```env
DISCORD_TOKEN=твой_токен
GUILD_ID=id_сервера          # чтобы команды появились сразу
LLM_API_KEY=ключ_модели      # необязательно, но без него нет ИИ-разбора
```

`GUILD_ID`: настройки сервера → «Виджеты»/«Информация о сервере» → ID сервера
(нужен включённый режим разработчика в Discord).

### 3. Запустить

```bash
npm start
```

В консоли появится ссылка-приглашение, список чек-листов и режим работы.
По умолчанию слэш-команды регистрируются при каждом старте.

### 4. Проверить

В топике с анкетой:

```
/review
```

Бот сам найдёт ссылку в стартовом сообщении топика. Можно и явно:

```
/review url:https://docs.google.com/document/d/…/edit
```

Проверить логику без Discord (удобно при настройке чек-листа):

```bash
npm run review -- "https://docs.google.com/document/d/…/edit"
```

## Команды

| Команда | Что делает |
| --- | --- |
| `/review` | Проверить документ. Без `url` ищет ссылку в топике/канале |
| `/review url:<ссылка>` | Проверить конкретный документ |
| `/review criteria:<имя>` | Применить сохранённый чек-лист |
| `/review file:<файл.md>` | Одноразовый чек-лист из вложения, без сохранения |
| `/review silent:true` | Показать результат только себе |
| `/criteria upload file:<файл.md>` | Загрузить/обновить чек-лист |
| `/criteria list` | Список чек-листов (⭐ — по умолчанию) |
| `/criteria show name:<имя>` | Скачать чек-лист файлом |
| `/criteria delete name:<имя>` | Удалить чек-лист |

`/criteria …` доступна тем, у кого есть право «Управление сервером», или роли
из `REVIEWER_ROLE_ID`.

Под результатом есть кнопка **«Перепроверить»** — пригодится после правок
документа.

## Чек-лист в `.md`

Чек-лист — обычный markdown-файл. Сверху необязательная «шапка» между `---`,
внутри — то, что бот сможет проверить формально; тело файла — инструкция для ИИ.

```markdown
---
name: Личное дело сотрудника ОВА
description: Проверка анкеты сотрудника Общественной Власти Альянса
version: 2
min_score: 70
required_sections:
  - ОСНОВНАЯ ИНФОРМАЦИЯ
  - БИОГРАФИЯ | БИОГРАФИЧЕСКАЯ СВОДКА
required_fields:
  - ИМЯ
  - ФАМИЛИЯ
  - ВОЗРАСТ
numeric_fields:
  - ВОЗРАСТ
  - РОСТ
  - ВЕС
allow_empty_fields:
  - ОТЧЕСТВО
  - БРАТЬЯ
min_words:
  total: 300
  БИОГРАФИЯ: 120
forbidden_placeholders:
  - секретно
  - неизвестно
forbidden_phrases:
  - копия
  - бессмертн
  - неуязвим
checks:
  min_section_words: 10
  age_from_birth_year: true
  bmi: true
---

# Что проверяем

- Соответствие лору (сектор-08, City 8, Альянс, 7-часовая война)…
- В биографии есть конкретные события, а не пересказ шаблона…
```

### Поля шапки

| Поле | Смысл |
| --- | --- |
| `name` | Название чек-листа (видно в отчёте) |
| `description` | Короткое пояснение |
| `version` | Произвольная метка версии |
| `model` | Переопределить модель ИИ для этого чек-листа |
| `min_score` | Минимальная оценка: ниже — вердикт «на доработку» |
| `required_sections` | Обязательные разделы. Алиасы через `\|`: `БИОГРАФИЯ \| БИОГРАФИЧЕСКАЯ СВОДКА` |
| `required_fields` | Обязательные поля (ищутся по названию, сравнение мягкое) |
| `numeric_fields` | Поля, в которых должно быть число |
| `allow_empty_fields` | Поля, где прочерк — норма (братья/сёстры, награды…) |
| `soft_sections` | Разделы, где пустота — «важно», а не критично (например, биография) |
| `min_words` | `total` — минимум слов в документе; `ИМЯ_РАЗДЕЛА: N` — минимум в разделе |
| `forbidden_placeholders` | Дополнительные заглушки к встроенному списку (`-`, `не указано`, `TODO`…) |
| `forbidden_phrases` | Подстроки, которых быть не должно (проверяются без учёта регистра) |
| `checks.min_section_words` | Минимум слов для любого обязательного раздела (по умолчанию 10) |
| `checks.age_from_birth_year` | Сверять возраст с годом рождения |
| `checks.bmi` | Проверять правдоподобие рост/вес |
| `checks.id_from_steamid` | Сверять ID с последними 3 цифрами SteamID |
| `checks.valid_until` | Ожидаемая дата в поле «Действительно до», например `"01.08.2035"` |

### Готовые примеры

| Файл | Что это |
| --- | --- |
| `data/criteria/ova-dossier.md` | **Досье сотрудника ОВА** — основной чек-лист. Правила собраны из реальных замечаний проверяющих в канале «состав» (30 топиков): титул, отчество, ID по SteamID, лорные города, биография, удостоверение и подписи |
| `examples/wl-zayavka.md` | Заявка на WL — образец для другого типа документа (OOC + короткая IC-легенда) |

Файлы из `examples/` бот не подхватывает автоматически — это образцы, чтобы
скопировать и поправить под себя. Загрузить в бота:

```
/criteria upload file: wl-zayavka.md
```

Проверить черновик чек-листа локально, не загружая его:

```bash
npm run review -- "https://docs.google.com/document/d/…/edit" examples/wl-zayavka.md
```

### Правила разбора документа

Бот тянет документ как `…/export?format=txt` и разбирает структуру:

- заголовок — строка без отступа в ВЕРХНЕМ РЕГИСТРЕ (или `# Заголовок`);
- поле — `НАЗВАНИЕ:` и значение на следующей строке (как в таблицах Google);
- `ПОДЗАГОЛОВОК:` без значения, за которым сразу идут другие поля, считается
  заголовком группы, а не пустым полем.

Если шаблон анкеты изменится, автопроверки могут «не увидеть» раздел. В этом
случае поправь `required_sections` (добавь алиас через `|`) или названия в
документе. Полный отчёт показывает, какие разделы бот реально нашёл:
`| Разделов | … |` и таблицу автопроверок.

## Как считается вердикт

```
оценка = (балл автопроверок + балл ИИ) / 2      (если ИИ выключен — только автопроверки)
```

Автопроверки начинают со 100 и снимают: критично −25, важно −8, мелочь −2.

Вердикт:

- **Принять** — ≥ 85 и нет критичных замечаний;
- **На доработку** — 55–84, либо есть критичное замечание, либо оценка ниже `min_score`;
- **Отклонить** — < 55 (или критичное замечание при оценке < 40).

ИИ не может «поднять» вердикт выше, если автопроверки нашли критичную проблему.

## Настройки `.env`

| Переменная | По умолчанию | Что это |
| --- | --- | --- |
| `DISCORD_TOKEN` | — | Токен бота (обязательно) |
| `DISCORD_CLIENT_ID` | из токена | ID приложения |
| `GUILD_ID` | — | Сервер для быстрой регистрации команд |
| `REVIEWER_ROLE_ID` | — | Роль, которой можно управлять чек-листами |
| `LLM_BASE_URL` | `https://api.deepseek.com/v1` | Любой OpenAI-совместимый API |
| `LLM_API_KEY` | — | Ключ. Пусто — без ИИ-проверки |
| `LLM_MODEL` | `deepseek-chat` | Модель |
| `LLM_TEMPERATURE` | `0.2` | Температура |
| `LLM_MAX_TOKENS` | `3000` | Лимит ответа |
| `LLM_TIMEOUT_MS` | `120000` | Таймаут запроса |
| `MAX_DOC_CHARS` | `60000` | Сколько символов документа отправлять в модель |
| `DEFAULT_CRITERIA` | первый в папке | slug чек-листа по умолчанию |
| `DEPLOY_COMMANDS` | `true` | Регистрировать команды при старте |

Примеры провайдеров:

```env
# DeepSeek
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat

# OpenAI
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini

# локальная модель через Ollama (бесплатно, но медленнее)
LLM_BASE_URL=http://localhost:11434/v1
LLM_API_KEY=ollama
LLM_MODEL=qwen2.5:14b
```

## Где что лежит

```
data/criteria/            чек-листы (.md) — сюда пишет /criteria upload
data/criteria/.history/   старые версии чек-листов
data/reports/             отчёты, созданные через npm run review
```

История версий чек-листа сохраняется автоматически при перезаписи — видно,
что и когда меняли.

## Автозапуск

**Windows (Планировщик задач):** действие «Запуск программы» →
`C:\Program Files\nodejs\node.exe`, аргументы `src/index.js`,
рабочая папка — папка бота. Запуск «При входе в систему».

**Linux/VPS:**

```bash
npm i -g pm2
pm2 start src/index.js --name ova-review
pm2 save && pm2 startup
```

## Если что-то не работает

| Симптом | Причина / решение |
| --- | --- |
| `npm install` падает с `ECONNRESET` | Похоже на блокировку npmjs провайдером. Включите зеркало: `npm config set registry https://registry.npmmirror.com` (потом можно вернуть `npm config delete registry`) |
| `Used disallowed intents` | В Developer Portal → Bot включить **MESSAGE CONTENT INTENT**. Бот попробует перезапуститься без него, но поиск ссылки в топике отключится |
| Команды не видны | Указан `GUILD_ID`? Перезапусти бота. Для глобальных команд Discord даёт до часа |
| `Google закрыл доступ к документу` | В документе: «Настройки доступа» → «Все, у кого есть ссылка» → «Читатель» |
| `Документ не найден` | Ссылка битая, документ удалён или это другой сервис (нужен именно Google Docs) |
| ИИ-проверка не выполняется | Нет `LLM_API_KEY` или провайдер вернул ошибку — она будет в embed и в консоли. Автопроверки работают всегда |
| Бот не находит раздел | Шаблон изменился: добавь алиас в `required_sections` через `\|` |
| Слишком строго/мягко | Правь `min_words`, `required_*`, `forbidden_*` и тело чек-листа — это и есть «настройка правил» |

## Ограничения

- Документ должен быть доступен по ссылке (бот не логинится в Google).
- Отчёты и вердикты — **рекомендация**. Финальное решение и теги в топике
  ставит проверяющий.
- Discord-эмбед ограничен по размеру: подробности всегда в приложенном `.md`.
- Проверка не «видит» картинки и вложенные изображения — только текст.
